# Implementation Plan — 2026-11-05 Field Brief

Owner brief (2026-11-05) covering six areas. Researched against the
codebase first; where the brief's generic wording conflicts with
this product's locked architecture (Tauri app + Odoo addon; NO
gateway, NO local agent, NO cloud in the print path — owner
decision, ADR set), the locked architecture wins and the intent is
implemented inside it.

## Research findings (codebase)

1. **Printers & Lab.** Protocol detection and capabilities already
   exist (print-core `detect_protocol`, `PrinterCapabilities`
   incl. `bins` from `DC_BINS`/`DC_BINNAMES`, `resolve_printer_bin_id`
   applies `dmDefaultSource`). Gaps were surfacing: bins never shown,
   no per-printer defaults, no tray on IPP (loud refusal), registry
   holds no capability snapshot.
2. **POS printing.** Silent/no-dialog + virtual-first-class +
   selection-wins shipped in 1.4.9–1.4.11. Remaining gap: a receipt
   image printed via GDI (office/virtual target) ignores the roll
   width when choosing the page size.
3. **Browser.** Single `WebviewWindow` "main", `on_new_window: Deny`,
   floating nav pill in the bridge. User-visible "WebView2" wording
   lives in the Control Center diagnostics (4 strings). Tauri's
   multi-webview `Window::add_child` requires the `unstable`
   feature (present in the pinned 2.12.x; webviews must be created
   from async contexts on Windows); all content webviews must share
   one `data_directory` so Odoo sessions/cookies are shared across
   tabs exactly like Odoo expects.
4. **Systray bar.** Lists live printers + selection (owner model);
   the icon is a FontAwesome glyph, and rows lack source details.
5. **Reprint.** Root cause found: `action_reprint` checks
   `report.group_ids & env.user.group_ids` — a manual intersection
   that ignores Odoo's administrator semantics, so an Administrator
   who lacks one specific report group (even one Odoo would let
   them manage) is refused with "You do not have access to the
   report used by this job."
6. **Dedup.** Device registry already has a unique (name, company)
   constraint with race-safe upsert; will be re-verified by test.

## Execution slices (each shipped green to main)

- **S1 (Item 5):** reprint access = Odoo semantics: administrators
  (`_is_admin()`) always allowed; other users checked with the
  implied-aware group set; regression tests incl. implied-group
  and admin cases.
- **S2 (Item 4):** systray icon = the app/module icon image; printer
  rows show connection source + protocol/class + driver details.
- **S3 (Item 3a):** user-visible "WebView2" wording removed from
  the diagnostics package and Control Center (neutral "embedded
  browser" wording, both languages).
- **S4 (Items 1+2):** trays surfaced end-to-end — CC capability
  chips include trays; per-printer stored defaults (paper, tray,
  duplex, color) editable per card in the Control Center, persisted
  in the app config, applied by the worker when the job does not
  specify them; IPP tray maps to `media-source` for standard names
  (others keep the loud refusal); POS receipt images printed via
  GDI are sized to the roll width when the target reports one.
- **S5 (Item 1):** capability snapshot (forms + trays + protocol)
  synced to the Odoo device registry from the systray (throttled,
  upsert on the existing unique key — no duplicates), shown
  read-only on the device form.
- **S6 (Item 3b):** tabbed browser: one window, a local tab-bar
  webview (Back/Forward/Reload, tab chips, new tab, Control Center
  button) + one child webview per tab sharing a single data
  directory; navigation restricted to the configured Odoo origin;
  POS navigations open in a new tab; on-origin `window.open`
  becomes a tab; the floating pill is removed. Tab policy is
  unit-tested; the command surface grows deliberately (tab_open
  remote-reachable, tab management local-only) and the gate +
  docs are updated.
